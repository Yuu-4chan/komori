# Komori documentation

These documents describe the current Komori application. Code and tests are the final authority; when a document disagrees with them, the document is corrected.

## Documents

- `product-principles.md` — product and implementation rules that stay stable.
- `architecture.md` — how Komori is built: an overview, a repository map, and each subsystem's contracts. Start here before changing code.
- `features.md` — what each screen offers, in brief.
- `design.md` — visual tokens and reusable component guidance; application and Reader theme sources remain the runtime authority.
- `real-data-and-safety.md` — source-file safety and how Komori treats EPUBs and dictionary archives.
- `privacy.md` — what Komori stores, where, and when it uses the network.
- `troubleshooting.md` — common problems and their fixes.
- `workflow.md` — development commands and repository conventions.
- `release-checklist.md` — how a release is made and the manual checks before publishing it.

Agent instructions for this repository are in `../AGENTS.md`.

## Documentation policy

Keep these files short and current. Describe the system as it is, not how it got there. When a choice needs its reason recorded, give it in a sentence beside the behavior it explains.
